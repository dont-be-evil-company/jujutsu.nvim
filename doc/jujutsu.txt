1. INTRODUCTION                                                 *jujutsu-intro*

jujutsu.nvim provides a Magit-inspired UI for the Jujutsu (jj) VCS.

No user commands are registered. Use the Lua API (see |jujutsu-api|).

==============================================================================
2. REQUIREMENTS                                         *jujutsu-requirements*

- Neovim 0.10+
- `jj` on PATH

Optional (pick at most one):

Diff:  diffview.nvim  or  codediff.nvim

Selections use the built-in fuzzy finder.

Forge review (see |jujutsu-review|):
  GitHub: `gh`  |  GitLab: `glab`  |  Forgejo/Codeberg & Bitbucket: `curl` + tokens

3. SETUP                                                         *jujutsu-setup*

>
  require("jujutsu").setup({
    kind = "tab",
    use_default_keymaps = true,
    disable_signs = false,
    signs = {
      add = { text = "┃" },
      change = { text = "┃" },
      delete = { text = "▁" },
      topdelete = { text = "▔" },
      changedelete = { text = "~" },
    },
    annotate = { panel_height = 16 },
    file_history = { limit = 200, panel_height = 16 },
    mappings = {
      status = { ["q"] = "Close" },
      popup = { ["c"] = "ChangePopup" },
    },
    integrations = {
      diffview = nil,  -- nil = auto, true/false = force
      codediff = nil,
    },
    diff_viewer = nil,  -- "diffview" | "codediff" | nil
    picker = nil,       -- nil | "builtin" | "auto" | "telescope" | "fzf-lua" | "snacks" | "mini"
    forge = {
      pr_integration = true,
      review = { enabled = true },
      bitbucket = { user = nil, token = nil },
      forgejo = { token = nil },
      hosts = {},
    },
  })
<

Example lazy.nvim keys (no `cmd`):
>
  keys = {
    { "<leader>gg", function() require("jujutsu").open() end },
    { "<leader>jb", function() require("jujutsu").annotate() end },
    { "<leader>jr", function() require("jujutsu").review() end },
  }
<

4. API                                                             *jujutsu-api*

                                                            *jujutsu.open()*
open({opts})              Open the status buffer, or a popup if opts[1] is set.

  Options: ~
    cwd    string   repository directory
    kind   string   tab|split|vsplit|floating|replace|auto|...
    [1]    string   popup name (change, bookmark, log, ...)

                                                           *jujutsu.close()*
close()                   Close the status buffer.

                                                         *jujutsu.refresh()*
refresh()                 Refresh the status buffer (and jjsigns / lualine).

                                                        *jujutsu.annotate()*
annotate({opts?})         Open `jj file annotate` for the current buffer
                          (or opts.path) at the cursor line (or opts.line).
                          Shows a bottom panel of commits that touched the
                          file (like Diff popup `dc`).

  Options: ~
    bufnr      integer  buffer number (default: current)
    line       integer  1-based line to focus
    path       string   absolute or repo-relative path
    revision   string   starting revision for annotate
    cwd        string   workspace directory hint

                                                         *jujutsu.resolve()*
resolve({opts?})          Open the three-pane merge editor for a working-copy
                          conflict. With no path, opens the only conflict or
                          asks you to pick one. See |jujutsu-merge|.

  Options: ~
    cwd     string   workspace directory hint
    root    string   workspace root
    path    string   repo-relative or absolute file

  Status: `R` on a conflict.

                                                          *jujutsu.review()*
review({opts?})           Open a forge PR/MR review in DiffView.
                          Picks an open PR when number is omitted.

  Options: ~
    number     integer|string   PR/MR number
    cwd/root   string           workspace directory

                                                     *jujutsu.issue_panel()*
issue_panel({opts?})      Open the Issue/PR conversation side panel.
                          Prompts for kind + number when omitted.

  Options: ~
    number     integer|string   issue or PR/MR number
    kind       "issue"|"pr"     topic kind (default: "pr" when number set)
    cwd/root   string           workspace directory

                                                      *jujutsu.forge_popup()*
forge_popup({opts?})      Open the Magit-style Forge popup (PRs, issues, CI).

  Options: ~
    cwd/root   string           workspace directory

                                                          *jujutsu.action()*
action({popup}, {action}, {args?})
                          Return a function that runs a popup action.
                          Useful for custom keymaps.
                          Example: `action("diff", "annotate")`

                                                         *jujutsu.setup()*
setup({opts})             Configure the plugin.

==============================================================================
5. MAPPINGS                                                   *jujutsu-mappings*

Customize via `setup({ mappings = { status = {...}, popup = {...} } })`.
Set a key to |v:false| to disable it.

Popup keys (defaults): ? b c d f g l m p r s u w

Status context: D E O B F P S o x  and navigation/fold keys
(`<tab>` toggles sections, working-copy file diffs, recent-commit
status, and bookmark commit history).

Log view: `<cr>` open commit, `S` open `--stat` view, `P` split popup.

Diff popup: `dd` / `dr` / `dt` side-by-side diffsplit; `dc` change history;
`da` annotate (file under cursor).

Forge popup (`g`): review PRs, browse/create PRs and issues, list/trigger CI
(see |jujutsu-forge|).

6. INTEGRATIONS                                           *jujutsu-integrations*

Selections (revisions, bookmarks, remotes, PRs, …) use the built-in fuzzy
finder by default. Set `picker` to use another UI:

- nil or `"builtin"` - built-in finder and input
- `"auto"` - snacks, then mini.pick, fzf-lua, telescope, then built-in
- `"telescope"`, `"fzf-lua"`, `"snacks"`, `"mini"`
- a function `function(opts, callback) end` where `opts` has `prompt`,
  `entries` (strings), `allow_multi`, and `allow_free_text`. Call `callback`
  once with nil, a string, or a list of strings.

`kind = "floating"` opens the status buffer in a float. Later plugin windows
(popups, diff, annotate, file history, CI, issue panel, the finder) are placed
inside that float instead of on the tabpage behind it. Other `kind` values are
unchanged.

Diff popup action "External viewer" uses diffview or codediff when available
(typically requires a git-colocated jj repository).

Diff popup `dd` / `dr` / `dt` open a side-by-side diffsplit tab (file list +
parent/from ↔ to) instead of a flat unified patch. `dc` opens change history
(same diffsplit, with a revision list). With a revision under the cursor it
pre-selects that change; with a file under the cursor it scopes history to that
path; otherwise repo-wide. Opening a change (`<CR>`) uses the same side-by-side
diff for that revision.

`da` opens annotate for the file under cursor (see |jujutsu-annotate|).
`g` opens the Forge popup (see |jujutsu-forge|); review is `g` then `r`.

Forge: when `forge.pr_integration` is true, bookmarks may show PR numbers for
the detected provider; `o` opens the PR or commit in the browser.

Lualine: >
  require("lualine").setup({
    sections = {
      lualine_b = require("jujutsu.lualine").prepend({ "branch" }),
      lualine_x = require("jujutsu.lualine").append({
        "encoding",
        "fileformat",
        "filetype",
      }),
    },
  })
<
`components()` returns a list - use `.prepend()` / `.append()` (or
`vim.list_extend`) to flatten it into a section. Do not nest the list as a
single entry (that causes "attempt to call a table value").
Repo-wide working-copy `+`/`~`/`-` line counts (refreshed on write / cwd /
focus, not BufEnter). Rev is prefixed with a branch icon; bookmarks are the
closest ancestors of `@` (with ahead count), like oh-my-posh. Also:
`.component()`, `.rev()`, `.bookmark()`, `.diff()`, `.status()`.

7. SIGNS                                                         *jujutsu-signs*

jjsigns show working-copy line changes in the signcolumn (add / change /
delete), similar to gitsigns but display-only (no hunk navigation or reset).

Signs come from `jj diff --git` against the working-copy parents. They refresh
on BufEnter / BufWritePost / FocusGained and when `.jj` changes (filewatcher).

Disable with `disable_signs = true`. Glyphs are configured under `signs`:
>
  signs = {
    add = { text = "┃" },
    change = { text = "┃" },
    delete = { text = "▁" },
    topdelete = { text = "▔" },
    changedelete = { text = "~" },
  }
<

Highlight groups: `JujutsuSignsAdd`, `JujutsuSignsChange`, `JujutsuSignsDelete`.

8. ANNOTATE                                                   *jujutsu-annotate*

Built-in `jj file annotate` (blame) UI.

Layout: annotated file on top (change id, author, date, content); bottom panel
lists commits that touched the file (same data source as Diff popup `dc`).
Selecting a commit highlights its lines and jumps to the first match.
Moving the cursor in the annotate buffer selects that line's commit in the
panel. When the window is narrow, author and date shrink, then each source
line is stacked under its metadata.

Keys in the annotate buffer: ~
  <CR>     Drill into the cursor line: commit message, line text, and the
           commits from file history that still appear in this file.
           <CR> in that list opens the file diff for the commit.
  ]c [c    Next or previous annotate hunk
  q        Close

Keys in the history panel: ~
  <CR> o   Highlight the commit
  <Tab>    Next or previous commit

Entry points: ~
- Diff popup `da` - file under cursor in the status buffer
- |jujutsu.annotate()| - current buffer and cursor line
- `require("jujutsu").action("diff", "annotate")`

Config: `annotate.panel_height` (default 16). File history limit comes from
`file_history.limit`.

Highlight groups: `JujutsuAnnotateHash`, `JujutsuAnnotateAuthor`,
`JujutsuAnnotateDate`, `JujutsuAnnotateCurrent`, `JujutsuAnnotateSelected`.

9. FORGE HUB                                                     *jujutsu-forge*

Magit-style hub for pull requests, issues, and CI across supported forges.
Actions are shown only when the detected forge reports capability support.

Entry points: ~
- Status popup key `g` (|ForgePopup|)
- |jujutsu.forge_popup()|

Popup actions (when available): ~
  r        review open PR/MR (see |jujutsu-review|)
  p        browse / search PRs (state, assignee/author, label, query)
  P        create PR
  o        open PR by number (conversation panel)
  i        browse / search issues
  I        create issue
  n        open issue/PR by number (prompt)
  c        list CI runs (open URL / cancel)
  t        trigger workflow / pipeline

Providers degrade gracefully (e.g. Bitbucket has no labels; draft PRs when
supported). Label colors from the forge are used in the conversation panel.

10. PR REVIEW                                                   *jujutsu-review*

Review open pull / merge requests in the built-in DiffView with local comments,
markdown yank, and forge submit.

Providers: ~
- github     via `gh`
- gitlab     via `glab`
- forgejo    Codeberg / Forgejo via REST (prompted per host, or
             `FORGEJO_TOKEN` / `CODEBERG_TOKEN`)
- bitbucket  Bitbucket Cloud via REST (prompted per workspace, or
             `BITBUCKET_USER` + `BITBUCKET_TOKEN`)

Credentials for Bitbucket / Forgejo are stored under
`stdpath("data")/jujutsu/credentials.json`. HTTP 401 prompts to
update or delete stored credentials.

Bitbucket API token scopes: ~
  read:pullrequest:bitbucket / write:pullrequest:bitbucket
  read:issue:bitbucket / write:issue:bitbucket
  read:pipeline:bitbucket / write:pipeline:bitbucket
  read:workspace:bitbucket
    Required to list assignees and PR reviewers (workspace members).
    Without it the issue-panel assignee picker (`a`) reports
    "No assignable users found". Create/update tokens at
    https://id.atlassian.com/manage-profile/security/api-tokens
    then re-enter or delete the stored credentials so the new
    token is picked up.

Approve / request-changes needs `write:pullrequest:bitbucket`.

Entry points: ~
- Forge popup `g` then `r`
- |jujutsu.review()|

Review DiffView keys: ~
  c        comment at cursor line
  a        reply to remote comment thread
  C        file comment
  v/V + c  range comment
  ;c       review-level comment
  e / i    edit unsubmitted comment at cursor
  x        delete unsubmitted comment at cursor
  f        toggle all files / files with comments
  R        refresh all remote comments (cache)
  gr       refresh remote comments for current file
  m / M    next / previous comment (diff moves cursor; file list scrolls only)
  r        toggle file reviewed (panel)
  y        yank structured markdown
  S        submit (Comment / Approve / Request changes; Draft = GitHub only)
  I        open Issue/PR conversation panel
  o        open in browser (file / PR line)
  ?        help

Remote inline threads (including replies) are shown as nested overlays.
Comments wrap to the diff window by default (`forge.review.wrap_comments`);
set `wrap_width` for a fixed column, or `wrap_comments = false` to truncate.
Each comment shows a metadata header (name · date) then the body on following
lines with a fixed indent (`forge.review.comment_indent`, default 4).
Comment bodies are treesitter-highlighted as markdown by default
(`forge.review.render_markdown`).
`a` posts a reply on GitHub, GitLab, Bitbucket, and Forgejo/Codeberg.

Sessions are stored under `stdpath("data")/jujutsu/reviews/`.
Bitbucket / Forgejo credentials under `stdpath("data")/jujutsu/credentials.json`.

11. ISSUE / PR CONVERSATION PANEL                         *jujutsu-issue-panel*

Full-height right split with issue or PR details and conversation comments.
Inline review threads remain in the DiffView overlays.
Labels render with forge bg/fg colors when provided.

Open: ~
- Forge popup browse / create / open-by-number
- Review DiffView `I` (see `issue_panel.keymaps.open`)
- Status / log `I` (PR on bookmark when present, else prompt)
- |jujutsu.issue_panel()|

Panel keys: ~
  c        post a comment
  e        edit comment under cursor
  x        delete comment under cursor
  l        set labels (multi-select)
  E        edit title / body
  C        close (or merge for PRs)
  r        refresh
  o        open topic in browser
  q        close

In DiffView, `o` opens the file at the head commit (file list) or the
PR/MR at the cursor line (diff buffers).

Description and comment bodies are treesitter-highlighted as markdown by
default (`issue_panel.render_markdown`); author / date headers stay plain.

Config (defaults): ~
>
  issue_panel = {
    enabled = true,
    width = 0.38,
    min_width = 48,
    max_width = 90,
    position = "right",
    render_markdown = true,
    keymaps = {
      close = "q",
      refresh = "r",
      comment = "c",
      edit_comment = "e",
      delete_comment = "x",
      edit_topic = "E",
      labels = "l",
      close_topic = "C",
      open = "I",
      browser = "o",
    },
  }
<

Providers: GitHub (`gh`), GitLab (`glab`), Bitbucket, Forgejo/Codeberg.

12. MERGE CONFLICTS                                             *jujutsu-merge*

Three panes: Incoming and Current on top, Result below. Incoming and Current
stay aligned. Added lines are highlighted against the base; removed lines stay
visible so the panes line up. Each change has a gutter checkbox. The result
is the file that gets written, and it stays editable.

Non-overlapping edits start checked. Overlapping edits start unchecked.
Checking both keeps Incoming's block, then Current's.

Keys (`mappings.merge`): ~
  <Space>   Toggle the change under the cursor
  A         Take all incoming
  C         Take all current
  B         Keep both sides of this overlap
  ]c [c     Next or previous overlap
  ]f [f     Next or previous conflicted file
  <CR>      Write the result into the working copy
  R         Rebuild the result from the checkboxes
  <Tab>     Cycle panes
  q         Close

A click in the sign column toggles that change. Overlaps left open are written
back as snapshot conflict markers so jj keeps them conflicted. `jj resolve`
only exports file conflicts with two sides. Other conflicts open the file.
Binary conflicts ask you to take one side.

Entry points: ~
- Status `R` on a conflict
- |jujutsu.resolve()|
